# Phase 7.7 — Scanner de données de carte dans le chemin d'ingestion

Date : 2026-09-21. Règle dure : **jamais lire, stocker ni migrer de données
de carte brutes** (PAN, CVV, numéros complets). Construit comme un composant
actif du chemin d'ingestion, pas comme un audit après coup. 260/260, goldens
byte-identiques (aucune fixture ne porte de donnée de carte — invariant testé
sur les six jeux réels).

## Où il s'exécute

1. **Parser générique** (`parseWithKnowledge`) : chaque unité source **et**
   chaque compagnon sont scannés **avant** toute entrée de format — une
   valeur retirée n'atteint jamais le canon, `sourceExtension._raw` ni
   `unmapped[]`. `report.pciFindings[]` (chemin + type, jamais la valeur) +
   avertissement `pci_card_data_stripped { count, kinds }`.
2. **Moteur CSV** (`convert`) : la table est scannée avant tout parser ; une
   colonne de la famille carte / identifiant, ou dont les valeurs ont la
   forme d'un PAN (masqué ou non), est **vidée** et rapportée
   (`pci_card_data_stripped { count, columns }`, localisé FR/EN).
3. **Extracteurs 7.5** : le même module `scanForCardData` s'applique à la
   capture — les fixtures naissent propres.

## Détection = données (`core/knowledge-ref/canon/pci.v1.json`)

| Signal | Contenu | Exemples réels (7.1) |
|---|---|---|
| Familles de **noms** | pan, cvv, iin, last4, expiry, holder, token (paiement/carte/passerelle seulement — `token` nu est un symbole monétaire chez BigCommerce), bank (IBAN, BIC…), credential (passwd, hash, secure_key, reset_password_token, api_key, secret) | PrestaShop `card_number / card_expiration / card_holder`, `passwd / secure_key` ; Shopware `hash` |
| **Conteneurs** | `credit_card`, `cc`, `paymentDetails`, `creditCardDetails`… : l'objet entier est retiré sauf ses champs de **marque** | BigCommerce `transaction.credit_card { card_iin, card_last4, expiry }` → `{ card_type }` ; Shopify `CardPaymentDetails` → `{ company, wallet }` |
| **Formes** de valeurs | PAN 13–19 chiffres **Luhn** (seulement en contexte carte : nom de famille, frère de famille ou conteneur — un GTIN-13 de ligne produit n'est pas une carte), PAN **masqué** (`•••• 4242`, `XXXX-1234`, `4242**…**4242`) partout, IBAN partout, expiration MM/YY en contexte carte, CVV 3–4 chiffres sous un nom cvv | |
| **Marque conservée** | `card_type`, `card_brand`, `credit_card_type`, `company`, `wallet` — un fait de paiement | `master`, `Visa` |

Garde-fous testés : `order.number`, `currency.token`, `global_unique_id`,
`download_expiry`, `order_key` / `cart_hash`, une colonne CSV « Number » de
commandes — jamais touchés.

## Rapport

Chemin + type + voie (`name` / `shape` / `container`) ; les valeurs ne sont
jamais recopiées, même dans les tests (assertion). Une valeur nulle est
retirée sans finding (rien à signaler).
