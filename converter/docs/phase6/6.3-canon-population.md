## 3. Règles parser (données, aucun code plateforme)

- **D3** (`shopify.products.admin-graphql.v1.json`) : `seo.title / seo.description`
  → `seoTitle / seoDescription` ; `metafields_from_pairs` reçoit
  `args.drop: ["global.title_tag", "global.description_tag"]` — la paire SEO
  est portée **une fois**, jamais dupliquée. `mm-google-shopping.*` est porté
  (jamais supprimé), typé, et écrit par la cible Shopify dans **son**
  namespace (`condition (product.metafields.mm-google-shopping.condition)`).
- **Dérivation canon** (`canon/fields.v1.json#derivations`, appliquée par le
  parser générique ET par l'étape de finition du moteur — donc aussi aux
  parsers CSV historiques) : `barcode ← premier de identifiers.gtin → ean →
  upc → isbn`, jamais par-dessus un `barcode` natif ; provenance
  `{ sourceField: <chemin source de l'identifiant retenu>, transform:
  'first_non_empty', method: 'structural' }` — typée, sans note libre.
- **Shopify, sentinelle** : `options_from_attributes` reçoit
  `dropIfValuesIn: ["Default Title"]` — un axe dont toutes les valeurs sont
  la sentinelle n'est pas un axe (`hasOnlyDefaultVariant`).
- **Poids par variante** : `weight_to_grams` lit `{ value, unit }` — `GRAMS`
  et `KILOGRAMS` coexistent sur un même produit (observé : 150 g / 10 kg).
- **Shopware, traductions** : `translations_from_entities` (inputs
  `translations + seoUrls`, `defaultWhere.languageId = 2fbb5fe2…`) ; la
  surface brute par langue (keywords, packUnit, customFields par locale) est
  gardée dans `sourceExtension.shopware.translations` via `copy_present`
  (rien de matérialisé quand l'association n'est pas chargée).
- Nouveaux transforms génériques : `is_set`, `copy_present`, `first_non_empty`,
  `translations_from_entities`, `translations_from_pairs` ; extensions :
  `metafields_from_pairs` (`namespace`, `type`, `drop`),
  `metafields_from_object` (`sets` companion), `weight_to_grams` (objet),
  `options_from_attributes` (`dropIfValuesIn`).
- Parser générique : une entrée `sourceExtension.*` dont le transform ne rend
  rien sur une source **absente** (null / tableau vide) ne matérialise pas de
  clé (une chaîne vide reste une valeur — Levi's `description_en: ""`
  inchangé).

| Cible | P2 namespace | P3 identifiers | P1 translations |

sont localisés FR/EN (`app/renderer/i18n.js`).

## 5. Reconnaissance (catalogue `fields.v1.json`, 66 → 74 champs)

- 7 champs `identifiers.*` (scope variante, noms EN/FR : EAN, GTIN, UPC, ISBN,
  MPN, HS Code, Country of Origin…). `barcode` garde les noms **plateforme**
  (Variant Barcode, UPC/EAN, « GTIN, UPC, EAN, or ISBN ») → les règles exactes
  des formats connus gagnent toujours ; une colonne littéralement nommée `ean`
  devient `identifiers.ean` (test `semanticAnalyze` mis à jour) et la
  dérivation remplit `barcode`.
- **Pont mapping** (`mapping.ts`, `analyzePlan` sémantique) : un canon
  *dérivant* un autre (identifiers.ean → barcode) atteint la règle du champ
  dérivé — `ruleByCanon['identifiers.ean'] = 'barcode'` ; donc une colonne
  « EAN » pré-remplit toujours la règle `barcode` d'un format connu. Piloté
  par `derivations`, pas un cas spécial.
- Famille `translations` (regex : `name_en`, `Title (fr)`, `description_nl-BE`…),
  transform structurel (`transform-aliases: null`) — le writer Learned la
  préserve ; la résolution locale + champ est l'objet de **6.7**.
