# Phase 5.7 — Formats issus du Scraper, sans parser par site

Objectif : prouver (ou infirmer) la thèse « aucun parser par site » sur des
sorties **réelles** d'Eloshon Scraper, puis sur un CSV totalement inconnu.

## Données réelles utilisées

`test/fixtures/scraper/` — exports pris tels quels dans
`%APPDATA%/Eloshon Scraper/data/csv` (tronqués par enregistrement, pas de PII) :

| Fixture | Site | Lignes | Colonnes | Particularité |
|---|---|---|---|---|
| `levis-be.csv` | levi.com/BE | 40 (sur 463) | 21 | `variants` JSON = coloris **frères**, `source_category` hiérarchique |
| `april-beauty-be.csv` | april-beauty.be | 15 | 19 | descriptions multi-lignes, prix |
| `lidl-de.csv` | lidl.de | 10 | 21 | allemand, EAN partiels, poids partiels |
| `colruyt-be.csv` | colruyt.be | 5 | 19 | pas de prix (pages liste), `weight_kg` |

## Résultat

- **Aucun code nouveau.** Une seule entrée Reference
  `core/knowledge-ref/formats/scraper.eloshon-export.v1.json` (signature
  `csv-header-set` : 8 colonnes requises + hints `color`/`variants`) couvre les
  deux versions du format (19 et 21 colonnes). Le moteur route via
  `routing: { platform: 'eloshon', entity: 'products' }` vers le parser
  générique (`Detection.format === 'knowledge'`).
- Les 4 exports : `unknownKeys: []`, aucun warning, conversion Shopify et
  WooCommerce OK, 1 ligne par produit.
- Fichier **inconnu** (fournisseur, FR, `;`) : sémantique → décisions →
  `learnFormat()` → `store.putLearnedFormat()` → reconnu par hash structurel →
  converti. Vérifié en test unitaire *et* dans l'app réelle (selftest :
  `learnWalk.recognised = true`, aperçu 3 lignes).

## `[OBSERVATION]` — ce que les données réelles ont appris au moteur

1. **`variants` du Scraper ≠ variantes canon (Levi's).** Chaque entrée
   `{code, type:'couleur', name:null, image}` est un *autre produit* de la
   famille (le `code` est un `source_product_id`, y compris le sien). Les
   traiter en variantes produisait 240 « variantes » pour 40 produits, sans
   valeur d'option. Réponse **générique et pilotée par données** :
   `structure.variants.siblingsWhen = { childPath: 'code', matches: 'source_product_id' }`
   — une liste qui contient l'unité elle-même est une liste de pairs → tous
   ses éléments vont dans `merchandising.related` (relation
   *identifiers-relation* du concept-map), provenance `structural`. Zéro
   règle « Levi's » dans le code.
2. **Le format Scraper est fixe entre sites** ; ce qui varie est le contenu.
   La règle 8 (« plusieurs formats par site ») s'applique donc aux *versions*
   du Scraper (19 vs 21 colonnes), pas aux sites. Une signature unique avec
   hints suffit ; le hash structurel reste le mécanisme des formats appris.
3. **Multilingue** (`name_en`, `description_en`, `slug_en`) : dupliqués du FR
   sur tous les sites observés → transform `differs_from` : ignoré quand
   identique, sinon conservé en `sourceExtension.eloshon.*` et listé
   `no-canon-field` (promotable). Le canon n'est pas touché
   (canon-evolution-open « multilingue »).
4. **Prix absent (Colruyt)** : `null`, jamais `0`. **Poids** en kg → grammes.
   **`hs_code`** (douane) : aucun champ canon → `sourceExtension` + unmapped.
5. **Unité d'un format appris** : inférée du nom de colonne (« Poids (kg) »),
   défaut déclaré dans `canon/transform-aliases.v1.json`, noté dans l'entrée
   apprise quand supposé.
6. **Handle** : dérivé du SKU puis du titre quand la source n'en a pas
   (provenance `method: 'default'`).

## Ce qui reste hors périmètre (et pourquoi)

- Formats appris **clients / commandes** : le parser générique ne produit que
  des `CanonProduct[]` (entité `products`). Les catalogues sont le cas du
  Scraper ; clients/commandes restent sur les parsers CSV existants jusqu'à 5.9.
- Un CSV inconnu dont les *valeurs* portent une structure (variantes en
  lignes parent/enfant sans colonne de référence) demande une décision
  structurelle que le moteur propose (`parentRef`) mais que le Learned writer
  n'exprime pas encore en `structure.variants` — la colonne est conservée
  (`preservationReason: ambiguous`), rien n'est perdu.
